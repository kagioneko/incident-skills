# Phase 0: 封じ込め判断（Containment）

> [!CAUTION]
> **本スキルは封じ込めコマンドを生成するだけで、実行しない。**
> ファイアウォール変更・セッション切断・インスタンス停止は不可逆に近い破壊的操作であり、
> 実行者を誤ると自分をロックアウトする。実行は必ずユーザーが行う。

---

## 大原則: 侵害されたホストの「外」から絞る

root を取られている可能性がある以上、**そのホスト上のファイアウォールは信用できない。**
攻撃者は `ufw disable` で戻せるし、iptables ルールを消せる。

### 強度順

| 強度 | 手段 | 攻撃者から解除できるか |
|---|---|---|
| **強** | クラウド管理プレーン（セキュリティグループ / VPCファイアウォール） | ❌ できない |
| **強** | VPS事業者のコンソールのパケットフィルタ | ❌ できない |
| 中 | ホスト上の `ufw` / `iptables` / `nft` | ⭕ **root を持っていれば解除できる** |

> [!IMPORTANT]
> **必ず、まず事業者のコンソールを開くよう案内すること。**
> ホスト上のコマンドは、コンソールにアクセスできない場合の次善策であり、
> 「絞れた」とみなしてはならない。

## 封じ込めの前に、5秒だけ証拠を取る

遮断した瞬間に消える情報がある。**取得コストはほぼゼロ、失うと二度と取れない。**

```bash
# 5秒で終わる。封じ込めの直前に必ず実行
umask 077
PRE="$(mktemp -d /var/tmp/ir-pre-containment.XXXXXX)"
chmod 700 "$PRE"

ss -tunap        > "$PRE/sessions.txt"
ps auxfww        > "$PRE/processes.txt"
w -h             > "$PRE/logged_in.txt"
lsof -n -P -i    > "$PRE/network_files.txt"
date -Is         > "$PRE/containment_time.txt"

echo "封じ込め前スナップショット: $PRE"
```

> [!NOTE]
> **`/tmp` に直接置かない。**
> tmpfs なら再起動で消える。パーミッションによっては他ユーザーからも読める。
> `/var/tmp` 配下に `mktemp -d` + `chmod 700` で作る。
> これらは接続元IPなどを含むため、収集後は証拠ディレクトリへ移して同じ扱いにする。

> [!WARNING]
> **遮断は攻撃者への通知になる。**
> まだ活動中なら、証拠を消しに来る・ワイパーを仕込む・別経路へ逃げる可能性がある。
> だからこそ「先に揮発性データ、次に遮断」の順序を守る。

## ブロックリストではなくアローリスト

> [!CAUTION]
> **「不審なIPをキックする」は効かない。**
>
> 攻撃元はIPもUser-Agentもローテーションする。
> （実例: 692リクエストに対してUser-Agent 105種類、送信元IPは複数）
> 1つ弾いても、明日は別のIPから来る。そして**すでに入られている**。

正しいのは、全部閉じてから、確認済みの経路だけ開ける形。

```bash
# ❌ 効かない（いたちごっこ、しかも既に入られている）
ufw deny from 104.196.5.24
```

> [!CAUTION]
> ### 具体的なコマンドはここに書かない
>
> ホスト上のファイアウォール操作は、**手順を誤ると自分が締め出される。**
> 以下は `../../incident-containment/SKILL.md` §5 を参照すること。そちらには次が含まれる。
>
> - **`ufw --force reset` を使わない**（破壊的操作であってロールバックではない）
> - 専用チェーン `IR_CONTAINMENT` を追加する最小差分方式
> - **IPv4 と IPv6 を分離する**（`ip6tables` に IPv4 CIDR を渡すと許可ルールが成立せず締め出される）
> - **`ipv6-icmp` を落とさない**（NDP と PMTUD に必須）
> - **Tailscale の維持に必要な outbound を開ける**（41641/udp, 443/tcp, 3478/udp, 53, 123）
>   これを忘れると、残したはずの脱出経路が切断後に再接続できなくなる
> - ロールバック手順を先に生成し、別端末へ保存してから実行する

### outbound を止めるのが最重要、ただし全遮断ではない

侵害時に怖いのは、入ってくることより**出ていくこと**。

- C2（指令サーバー）との通信
- 収集済みデータの持ち出し
- 追加ペイロードのダウンロード

ただし、止めると以下も止まる。ユーザーに提示すること。

- 監視・死活監視エージェント
- バックアップジョブ
- 証明書の自動更新（certbot）
- パッケージ更新

そして、**自分の帰り道まで塞がないこと。**

## 既存セッションは遮断しても切れない

ファイアウォールは**新規接続**を止めるが、確立済みのTCPコネクションは残る。

```bash
# 現在のsshdセッション一覧（先に記録）
ps -eo pid,user,tty,lstart,cmd | grep '[s]shd:'

# 自分のセッションを確認してから、それ以外を落とす
echo "自分のPPID: $PPID / TTY: $(tty)"

# ※ このコマンドは提示のみ。実行はユーザーが対象を確認してから
# kill <対象PID>
```

> [!CAUTION]
> **自分のセッションを落とすと復旧できなくなる場合がある。**
> コンソール/VNCからの復旧手段を確認してから実行すること。

## 判断マトリクス

| 状況 | 判断 | 最優先アクション |
|---|---|---|
| **現在進行形で外部へ通信している** | 即封じ込め | 管理プレーンで **outbound から**遮断 |
| **認証情報の悪用が継続中** | 失効が先 | **クリーン端末**から失効・全セッション取消 |
| **メモリ上の証拠が重要** | 停止しない | ネットワークのみ切断。インスタンスは停止しない |
| **ランサム・破壊活動が進行中** | 即停止 | スナップショット取得 → インスタンス停止 |
| **過去ログの調査だけ** | 封じ込め不要 | スナップショット取得 → 収集スクリプト |
| **業務影響が極めて大きい** | ユーザー判断 | 影響とリスクを提示して待つ |

### インスタンス「停止」の前に

停止するとメモリ上の証拠が消える。判断は以下。

- **メモリ証拠が要る** → 停止せずネットワーク隔離のみ
- **破壊が進行中** → **先にディスクスナップショットを取ってから**停止
- どちらか迷う → **スナップショットを取る**（取っておけば後で選べる）

## 絶対にやってはいけないこと

> [!CAUTION]
> ### 1. 新しい認証情報を侵害環境に入力しない
>
> 侵害されたホスト上で、新しいAPIキー・パスワード・SSH秘密鍵を作らない、置かない、貼らない。
> **まだ root を取られているなら、新しい鍵も即座に漏れる。**
>
> 失効と再発行は必ず**クリーンな端末**から行う。
> 新しい鍵の配備は、**新環境を構築してから**。
>
> ### 2. 侵害済み環境を直して再利用しない
>
> バックドアを消したつもりでも、見つけられていない永続化が残っている可能性がある。
> 信頼できるソースから新環境を構築して移行するのが標準。
>
> ### 3. ホスト上のファイアウォールだけで「絞れた」と判断しない
>
> root を取られていれば解除できる。管理プレーン側と併用すること。

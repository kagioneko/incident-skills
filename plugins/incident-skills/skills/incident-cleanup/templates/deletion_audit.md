## 承認記録

受け取った `DELETE-CONFIRM` を**そのまま貼る。**

```
DELETE-CONFIRM
/root/ir/evidence/working-copy/...
/root/ir/evidence/working-copy/...
```

| 項目 | 内容 |
|---|---|
| 承認受領日時 (UTC) | |
| 承認対象件数 | |
| 提示した一覧との一致 | ✅ 一致 / ❌ 不一致（不一致なら中止） |

### 検証結果

各パスについて、以下をすべて確認したこと。

| # | パス | 絶対パス | 通常ファイル | リンクでない | realpath が working-copy 内 | 同一FS |
|---|---|---|---|---|---|---|
| 1 | | ✅ | ✅ | ✅ | ✅ | ✅ |

**1つでも ❌ があれば、バッチ全体を中止する。部分実行はしない。**

## 削除記録

| 日時(UTC) | ファイル | サイズ | 承認元 | 判定 |
|---|---|---|---|---|
| | | | `DELETE-CONFIRM` 受領分 | ユーザー明示指示 |

### 判定の3区分

| 判定 | 意味 |
|---|---|
| **ユーザー明示指示** | `DELETE-CONFIRM` で対象を特定した承認があった |
| **ユーザー承認済み・エージェント判断** | 承認はあったが、対象の特定はエージェント側が行った |
| **エージェント独断** | 指示も承認もなかった ← **発生した時点で異常** |

> [!CAUTION]
> **「エージェント独断」が1件でもあれば、報告の最上部に明記する。**
> それは削除の問題ではなく、**権限設計が機能していない**という所見である。
>
> 本スキルはこの区分が発生しない設計になっているが、
> 発生した場合に隠さず記録できるよう、区分自体は残してある。

- [ ] `evidence/original/` が変更されていない（マニフェスト照合で確認）

- [ ] 本監査ログを記録した

```bash

cd evidence/original/<展開先> && sha256sum -c MANIFEST.sha256 --quiet && echo "OK"
```

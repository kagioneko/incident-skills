# インシデント後クリーンアップ（削除）

> [!CAUTION]
> **このスキルはモデルから自動的に呼び出されない。**
> Codexでは `agents/openai.yaml`、Claude Codeではインストール時のfrontmatterにより、ユーザーが明示した場合のみ起動する。
>
> これは意図的な設計である。削除は副作用のある不可逆操作であり、
> 「クリーンアップして」「危険なファイル消して」といった依頼から
> 自動的に到達してはならない。

---

## 起動の前提条件

以下がすべて満たされていなければ、削除を実行しない。

- [ ] `incident-response` による分析が完了している
- [ ] フォレンジックレポートが作成済みである
- [ ] 証拠アーカイブが作成され、ハッシュが別経路に控えられている
- [ ] 削除対象がすべて `working-copy/` 配下である
- [ ] ユーザーが本スキルを明示的に呼び出した

ひとつでも欠けていれば、**その旨を伝えて停止する。**

---

## 絶対に削除しないもの

`original/` 配下のすべて。例外なし。

以下は `working-copy/` にあっても、単独では削除対象にしない
（フォレンジック証拠として保存する。中身の秘匿が必要なら**マスク版を別に作る**）。

- `.bash_history` / `.mysql_history` / `.psql_history` / `.zsh_history`
- `.ssh/known_hosts` / `.ssh/authorized_keys`
- `auth.log` およびシステムログ一式
- AI エージェントのセッションログ（`~/.claude/projects/` 等）
- `timeline_mac.txt` / `all_authorized_keys.txt` / `MANIFEST.sha256`

> [!IMPORTANT]
> 平文の認証情報が含まれているファイルでも、**分析前に消してはならない。**
> 正しい順序は「保全 → 分析 → マスク版作成 → 生データ削除」。
> 衛生管理として削除が妥当であることと、いま削除してよいことは別の判断である。

---

## 言語解釈の規則

| ユーザーの発言 | 解釈 | 動作 |
|---|---|---|
| 「Continue」 | 作業の続行 | **削除の許可ではない。** 削除は実行しない |
| 「消せる？」「消せますか？」 | 可能性の質問 | 対象一覧を提示して確認を返す |
| 「危険そうなファイル消して」 | 曖昧な依頼 | 対象を列挙し、確認トークンを求める |
| 「この5個を削除して」 | 対象は特定されているが、トークンなし | **一覧を提示し、確認トークンを求める** |
| `DELETE-CONFIRM` + 絶対パス列 | **明示的承認** | 実行してよい |

> [!CAUTION]
> 曖昧な依頼を「意図はこうだろう」と補完して実行しないこと。
> 削除は不可逆であり、誤りのコストが非対称である。

---

## 確認トークン `DELETE-CONFIRM`

削除の承認は、**この形式でのみ有効**とする。

```
DELETE-CONFIRM
/root/ir/evidence/working-copy/discord_bot/.env
/root/ir/evidence/working-copy/vps-spirit/youtube_token.json
```

> [!IMPORTANT]
> ### 検証は、目視ではなくツールで行う
>
> ```bash
> printf '%s\n' "$CONFIRM_TEXT" \
>   | scripts/verify_delete_confirm.sh --working-copy /path/to/evidence/working-copy \
>       --proposed /path/to/proposed_list.txt
> ```
>
> **exit 0 のときだけ削除してよい。** 標準出力に検証済みの絶対パスが返る。
> 1件でも失敗すると何も出力せず exit 1 になる（部分実行の防止）。
>
> 以下の規則は、このツールが機械的に検証する。
> **モデルが目視で確認するのではない。**

### 検証規則（すべて満たさなければ実行しない）

1. 1行目が `DELETE-CONFIRM` のみであること
2. 2行目以降が**絶対パス**であること（相対パス、グロブ `*`、`~` は無効）
3. **通常ファイルであること**（ディレクトリ・シンボリックリンク・デバイス等は不可）
4. 各パスを `realpath` で解決し、**シンボリックリンク解決後も** `working-copy/` 配下であること
5. **マウントポイントを跨いでいないこと**（bind mount 対策）
6. 直前に提示した一覧に含まれるパスであること（提示していないパスが混ざっていたら全体を中止）
7. 「絶対に削除しないもの」に該当しないこと

```bash
WORKING="$(realpath /root/ir/evidence/working-copy)"
WORKING_DEV="$(stat -c %d "$WORKING")"

for p in "${TARGETS[@]}"; do
    case "$p" in /*) ;; *) echo "REJECT: 絶対パスではない: $p"; exit 1;; esac
    case "$p" in *'*'*|*'?'*|*'~'*) echo "REJECT: グロブ/チルダ: $p"; exit 1;; esac

    # シンボリックリンクそのものは対象にしない
    [ ! -L "$p" ] || { echo "REJECT: シンボリックリンク: $p"; exit 1; }
    # 通常ファイルのみ（ディレクトリは別手順）
    [ -f "$p" ]   || { echo "REJECT: 通常ファイルではない: $p"; exit 1; }

    rp="$(realpath -e "$p" 2>/dev/null)" || { echo "REJECT: 解決できない: $p"; exit 1; }
    case "$rp" in
        "$WORKING"/*) ;;
        *) echo "REJECT: working-copy の外を指している: $p -> $rp"; exit 1;;
    esac

    # bind mount 対策: 同じファイルシステム上にあるか
    [ "$(stat -c %d "$rp")" = "$WORKING_DEV" ] \
        || { echo "REJECT: 別のマウントの実体を指している: $p"; exit 1; }
done
```

削除も限定する。**`rm -rf` は使わない。**

```bash
for p in "${TARGETS[@]}"; do
    rm -- "$p"        # または unlink -- "$p"
done
```

> [!IMPORTANT]
> **3番と5番が要点。**
>
> `DELETE-CONFIRM` にディレクトリを書けてしまうと、`rm -rf` 一発で配下の
> `.bash_history`・AIセッションログ・`MANIFEST.sha256` まで巻き込める。
> 検証しているのは承認されたパスだけで、**配下の全ファイルではない。**
>
> また `working-copy/` 配下に bind mount があると、文字列も `realpath` も
> working-copy 内なのに、**別領域の実体を削除できてしまう。**
> デバイス番号で同一ファイルシステムかを確認する。

### ディレクトリを削除する場合（別手順）

通常の `DELETE-CONFIRM` では受け付けない。以下をすべて実施する。

1. 配下のファイルを**全列挙**してユーザーに提示する
2. 全ファイルを個別に `DELETE-CONFIRM` で承認してもらう
3. `mountpoint -q` で配下にマウントポイントが無いことを確認
4. 「絶対に削除しないもの」が配下に無いことを確認
5. ファイルを個別に `rm --` で削除
6. **最後に空になったディレクトリだけを `rmdir` する**

`rmdir` は空でなければ失敗する。これが最後の安全網になる。

---

一件でも検証に失敗したら、**そのバッチ全体を中止**して報告する。
部分実行はしない。

---

## 手順

### 1. 対象一覧の提示

削除候補を、以下の情報とともに一覧化する。

| ファイル | サイズ | 分類 | 削除理由 | 証拠価値 |
|---|---|---|---|---|

**証拠価値がある**と判定したものは、リストの一番上に置き、
「これらは残すことを推奨する」と明記する。

### 2. 明示的承認の取得

一覧を提示したあと、**一度停止する。**
ユーザーから `DELETE-CONFIRM` 形式の承認を得るまで、削除を実行しない。

「Continue」や無言、肯定的な相槌、「消していいよ」は承認とみなさない。

提示の最後に、そのまま貼り返せる形を示す。

```
削除を承認する場合は、以下をそのまま送ってください。
不要な行は削除してください。

DELETE-CONFIRM
/root/ir/evidence/working-copy/discord_bot/.env
/root/ir/evidence/working-copy/vps-spirit/youtube_token.json
```

### 3. スコープの確認

削除実行の直前に、対象がすべて以下の条件を満たすか再確認する。

- `working-copy/` 配下であること
- 承認された一覧に含まれていること
- `realpath` 解決後も `working-copy/` 配下であること（シンボリックリンク対策）
- 「絶対に削除しないもの」に該当しないこと

**一件でも条件を外れていれば、そのバッチ全体を中止し、報告する。**

> [!IMPORTANT]
> 作業範囲が途中で広がっていないか、必ず確認する。
> ワークスペース内の作業からホームディレクトリ直下へ、
> といったスコープの越境は、それ自体が停止理由である。

### 4. 実行と記録

削除の実行と同時に、作業ディレクトリの `evidence/audit/deletion_audit.md` へ全件を記録する。
雛形は本スキルの `templates/deletion_audit.md` を使う。

```markdown
| 日時 | ファイル | サイズ | 承認元の発言 | 判定 |
|---|---|---|---|---|
| 2026-08-01 14:32 | working-copy/x/.env | 1.2KB | 「この5個消して」 | ユーザー明示指示 |
```

判定は以下の3区分。

- **ユーザー明示指示**: 対象を特定した削除指示があった
- **ユーザー承認済み・エージェント判断**: 承認はあったが対象の特定はエージェント側
- **エージェント独断**: 指示も承認もなかった ← **この区分が発生した時点で異常。即報告する**

### 5. 事後報告

削除完了後、件数・内訳・区分ごとの集計を報告する。
「エージェント独断」が1件でもあれば、それを最上部に明記する。

報告には以下の3項目を**必ず併記する**（3兄弟共通ルール）。

```markdown
## クリーンアップ結果

### 削除した対象
- working-copy/discord_bot/.env（1.2KB / ローテーション済みのため）
- ... 計 N 件

### 残した対象（削除しなかったもの）
- working-copy/.bash_history — フォレンジック証拠のため保持
- working-copy/.mysql_history — 同上
  ※ 平文パスワードを含むため、マスク版を別途作成済み

### 原証拠の保全場所
- evidence/original/ （読み取り専用マウント、未変更）
- アーカイブ: ir-evidence.server-01.20260801_051200.tar.gz
- SHA-256: a1b2c3...（別経路に控え済み）
```

**「クリーンアップ完了」で終わらせない。**
何を残したか、原証拠がどこにあるかまで書いて、はじめて報告になる。
